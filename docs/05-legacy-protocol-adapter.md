# Legacy Protocol Adapter

This document specifies how the protocol adapter differs from the legacy protocol adapter. The glossary [`CONTEXT.md`](../CONTEXT.md#language) defines the terms of the legacy stack. Before the Galileo upgrade, each chain used the legacy protocol adapter, which runs `contracts/v1.1.0` of this repository. The Galileo upgrade replaces it with the protocol adapter, once for each chain. After it, each change of the code is an upgrade in place. [`06-state-migration.md`](./06-state-migration.md) specifies how a migrated chain copies the state of its legacy protocol adapter.

## 1. Differences

| Part                        | Legacy protocol adapter                                                                                                                                                                            | Protocol adapter                                                                                                                  | Specified in                                                                           |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Code                        | Immutable                                                                                                                                                                                          | An ERC-1967 proxy in the UUPS pattern. The owner sets a new implementation.                                                       | [`01-upgradeability-and-ownership.md`](./01-upgradeability-and-ownership.md)           |
| Stop                        | `emergencyStop()` pauses it, and nothing lifts the pause.                                                                                                                                          | `pause()` and `unpause()`. The owner can lift each pause.                                                                         | [`01-upgradeability-and-ownership.md`](./01-upgradeability-and-ownership.md)           |
| Storage                     | Normal storage slots                                                                                                                                                                               | One ERC-7201 namespace for each state contract                                                                                    | [`01-upgradeability-and-ownership.md`](./01-upgradeability-and-ownership.md)           |
| Version                     | `getVersion()` returns a `bytes32`.                                                                                                                                                                | The constant string `VERSION`, and `getImplementation()`                                                                          | [`01-upgradeability-and-ownership.md`](./01-upgradeability-and-ownership.md)           |
| Proofs                      | A compliance proof for each compliance unit and a resource logic proof for each resource, or one aggregation proof if the transaction has one. The journal has the RISC Zero serialization.        | Only the aggregation proof and the delta proof. The protocol adapter calculates the journal digest itself, from the ABI encoding. | [`02-proofs-state-and-events.md`](./02-proofs-state-and-events.md)                     |
| Delta proof                 | Signs the Keccak-256 hash of all tags of the transaction, in the order of the compliance units                                                                                                     | Signs the Keccak-256 hash of the action tree roots                                                                                | [`02-proofs-state-and-events.md`](./02-proofs-state-and-events.md)                     |
| Transaction without actions | Accepted. For a transaction without tags, it checks no proof and stores no root.                                                                                                                   | Rejected (`EmptyTransactionNotAllowed`)                                                                                           | [`02-proofs-state-and-events.md`](./02-proofs-state-and-events.md)                     |
| Nullifier set               | Counts and lists its nullifiers                                                                                                                                                                    | A mapping that only shows whether it contains a nullifier                                                                         | [`02-proofs-state-and-events.md`](./02-proofs-state-and-events.md)                     |
| Kinds and logic refs        | No controls. Each kind point comes from the kind of the resource, so no two kinds balance against each other. The owner cannot stop a single resource logic.                                       | `setKindTreeRoot` and `denyLogicRefs`                                                                                             | [`03-kind-tree-root-and-denylists.md`](./03-kind-tree-root-and-denylists.md)           |
| Actions                     | Compliance units of exactly one consumed and one created resource. It processes the resources in pairs, in the order of the units, and finds the resource logic proof of each resource by its tag. | One ordered list of resources. The order of the list sets the order of the external calls.                                        | [`04-resource-order-and-external-calls.md`](./04-resource-order-and-external-calls.md) |
| Processing of a resource    | It checks the resource logic proof if the transaction has no aggregation proof, makes the external calls, and then adds the nullifier or the commitment.                                           | It adds the nullifier or the commitment, and then makes the external calls. It checks the proofs after the last action.           | [`04-resource-order-and-external-calls.md`](./04-resource-order-and-external-calls.md) |

## 2. Commitment tree

|                  | Legacy protocol adapter                                                                     | Protocol adapter                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Storage at setup | The roots of the empty subtrees for all 256 levels                                          | One entry. The tree adds one level each time a commitment fills it.                                                           |
| Add a commitment | Calculates the hash of each level, stores it where it is a left child, and returns the root | Writes one left sibling and the commitment count, and calculates no root. A commitment that fills the tree also adds a level. |
| Latest root      | The last stored root                                                                        | Calculated when read, from the left siblings                                                                                  |
| Historical roots | A set that counts and lists them                                                            | A mapping that only shows whether a root is historical                                                                        |
| Roots stored     | One for each transaction with tags                                                          | One for each transaction that adds commitments, after its last action                                                         |

`isCommitmentTreeRootContained` of the legacy protocol adapter is `isCommitmentTreeRootHistorical` in the protocol adapter.

## 3. Events

| Event                                                                    | Legacy protocol adapter                     | Protocol adapter                                                                                                                           |
| ------------------------------------------------------------------------ | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `TransactionExecuted`                                                    | All tags and logic refs of the transaction  | The transaction ID                                                                                                                         |
| `ActionExecuted`                                                         | The action tree root and the number of tags | The action tree root, and the nullifiers and the commitments with their logic refs, in two arrays. Each array keeps the order of the list. |
| `KindTreeRootUpdated`, `LogicRefDenied`                                  | —                                           | Only in the protocol adapter                                                                                                               |
| `Initialized`, `Upgraded`, `Unpaused`                                    | —                                           | Only in the protocol adapter, from OpenZeppelin                                                                                            |
| `CommitmentTreeMigrated`, `NullifierBatchMigrated`, `MigrationFinalized` | —                                           | Only from the migrational implementation ([`06-state-migration.md`](./06-state-migration.md))                                              |

`ForwarderCallExecuted`, `CommitmentTreeRootAdded` and the four app data events are the same in both.

## 4. Removed functions

The protocol adapter does not have these functions of the legacy protocol adapter:

- `emergencyStop` and `isEmergencyStopped`: `pause`, `unpause`, `paused()` and `riscZeroVerifierPaused()` take their place ([`01-upgradeability-and-ownership.md`](./01-upgradeability-and-ownership.md)).
- `simulateExecute`.
- `getVersion`, `getRiscZeroVerifierRouter` and `getRiscZeroVerifierSelector`: the constant `VERSION` and the immutables `RISC_ZERO_VERIFIER_ROUTER` and `RISC_ZERO_VERIFIER_SELECTOR` take their place.
- The verification of each separate proof.
- The calculation of the action tree root on the chain: the aggregation proof covers it.
- The functions that count and list the historical roots and the nullifiers. The state migration reads these values from the legacy protocol adapter, and no other function needs them.
